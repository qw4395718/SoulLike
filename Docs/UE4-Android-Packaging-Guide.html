2. 安装 JDK 8

2.1 下载

访问 Adoptium 官网：https://adoptium.net/temurin/releases/?version=8

下载 Windows x64 MSI 安装包，安装路径改为：D:\Java\jdk1.8

2.2 设置环境变量

变量名变量值
JAVA_HOMED:\Java\jdk1.8
Path 追加%JAVA_HOME%\bin

2.3 验证

java -version

预期输出：openjdk version "1.8.0_492"

⚠️ 避坑（已踩）：JDK 版本冲突
如果系统中同时安装了 JDK 17，java 命令会优先走 Path 里靠前的条目。执行 where java 查看顺序，删掉 JDK 17 的 Path 条目，不要只改 JAVA_HOME。

3. 安装 Android SDK / NDK

3.1 下载 Cmdline Tools

访问：https://developer.android.com/studio#command-line-tools-only

下载 commandlinetools-win-9477386_latest.zip，解压到 D:\Software\Android\cmdline-tools

3.2 修正目录结构

⚠️ 避坑（已踩）：sdkmanager 目录层级
新版 Cmdline Tools 要求放在 <sdk_root>\cmdline-tools\latest\ 下，不能直接放在 cmdline-tools\bin。 
cd /d D:\Software\Android\cmdline-tools
mkdir latest
move bin latest\bin
move lib latest\lib
move NOTICE.txt latest\
move source.properties latest\

最终结构：D:\Software\Android\cmdline-tools\latest\bin\sdkmanager.exe

3.3 安装 SDK 组件

⚠️ 避坑（已踩）：sdkmanager 需要 JDK 11+
新版 sdkmanager 编译目标为 JDK 11，JDK 8 无法直接运行。需要临时切到 JDK 17 安装，装完再切回 JDK 8。 
:: 临时切到 JDK 17
set JAVA_HOME=C:\Program Files\Microsoft\jdk-17.0.9-hotspot
set Path=%JAVA_HOME%\bin;%Path%

:: 安装组件
cd /d D:\Software\Android\cmdline-tools\latest\bin
set SKIP_JDK_VERSION_CHECK=true
sdkmanager "platforms;android-30"
sdkmanager "build-tools;30.0.3"
sdkmanager "ndk;21.4.7075529"
sdkmanager "platform-tools"

:: 切回 JDK 8
set JAVA_HOME=D:\Java\jdk1.8
set Path=%JAVA_HOME%\bin;%Path%
java -version

3.4 确认 NDK 目录结构

sdkmanager 安装的 NDK 21.4.7075529 与 UE4.26 完全兼容，无需额外下载 r21e。

只需要确认 platforms 目录存在即可：

dir D:\Software\Android\ndk\21.4.7075529\platforms

应该有 android-16 到 android-30 等子目录。

⚠️ 避坑（已踩）
后续在 UE4 编辑器中配置 NDK API Level 时，一定要填 android-21（带前缀），不能只填 21。详见第 4 节。

3.5 添加 Path 环境变量

系统变量 → Path → 新建：

D:\Software\Android\platform-tools
D:\Software\Android\cmdline-tools\latest\bin

验证：adb version

4. 配置 UE4 编辑器

启动 UE4.26 → 打开项目 → Edit → Project Settings → Platforms → Android SDK

字段值
Location of Android SDKD:\Software\Android
Location of Android NDKD:\Software\Android\ndk\android-ndk-r21e
Java SDK (JDK)D:\Java\jdk1.8
SDK API Levelandroid-30
NDK API Levelandroid-21 ← 注意前缀
❌ 避坑（已踩）：NDK API Level 命名格式
不要只填 21，要填 android-21（匹配 NDK platforms 目录命名格式）。否则报错：The NDK API requested 'NDK r21' not installed。

填写后点击 Accept SDK License，路径应全部标绿。

6. 打包 APK

6.1 确认 JDK 版本

java -version

必须显示 1.8.0_xxx。

6.2 选择打包

File → Package Project → Android → ASTC

选取输出目录（建议：D:\Code\SoulLike\AndroidBuild）

6.3 等待编译完成

  • C++ 编译：5-15 分钟
  • Cook + 打包 APK：5-10 分钟
  • 最终生成：SoulLikeDemo-Android-Shipping.apk

注意：打包期间不要关闭编辑器和命令行窗口。

7. 常见踩坑记录

❌ 坑1：JDK 版本冲突
现象：java -version 显示 17.0.9，但已安装了 JDK 8。
原因：系统中 JDK 17 的 Path 条目排在 JDK 8 前面。
解决：where java 查看路径顺序，删掉 JDK 17 的 Path 条目。
❌ 坑2：sdkmanager 报 "Could not determine SDK root"
原因：新版 Cmdline Tools 要求放在 <sdk_root>\cmdline-tools\latest\。
解决：在 cmdline-tools 下创建 latest 目录，把 bin/lib 等移入其中。
❌ 坑3：sdkmanager 需要 JDK 11+
原因：新版 sdkmanager 编译目标为 JDK 11，JDK 8 无法运行。
解决：安装 SDK 组件时临时设 JAVA_HOME 为 JDK 17，装完后切回 JDK 8。
❌ 坑4：（已排除）NDK 版本兼容性
实际 NDK 21.4.7075529 完全兼容 UE4.26，此坑已被排除。
真正的配置错误是坑5的 API Level 命名格式。
❌ 坑5：NDK API Level 命名格式
原因：UE4 编辑器中 NDK API Level 字段填了 21，实际需要 android-21。
解决：改为 android-21。
❌ 坑6：Android Clang 编译错误
原因：Android 使用 Clang 编译器，比 MSVC 更严格。常见问题包括 switch 类型不匹配和使用了 Windows 专有宏（如 INT）。
解决：修正类型匹配，用 static_cast<int32>() 替代平台宏。
