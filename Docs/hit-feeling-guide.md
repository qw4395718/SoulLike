## 1 总纲

### 1.1 什么是打击感

打击感不是单一效果，而是多个系统在命中的一瞬间**同时叠加**产生的综合感受：

```
命中瞬间 (0~200ms)
  +-- 命中停顿（Hit Stop）        所有动作暂停几帧
  +-- 相机震动（Camera Shake）    屏幕抖动
  +-- 音效（Hit Sound）           骨骼断裂/金属碰撞声
  +-- 粒子（Blood / Spark）       血液飞溅/火花
  +-- 屏幕特效（Hit Flash）       白/红闪屏
  +-- 受击动画（Hit React）       目标后仰/硬直
  +-- 伤害数字（Damage Number）   飘字
  +-- 手柄震动（Controller Rumble）振动反馈
```

**关键原则**：所有反馈必须在命中判定后的 1~3 帧内同时触发，时间差会导致打击感急剧下降。

### 1.2 类魂游戏的特殊性

| 特性 | 对打击感的影响 |
|------|--------------|
| 动作偏慢、权重感强 | Hit Stop 可以比动作游戏更长（8~15 帧） |
| 耐力管理 | 体力不足时的攻击应该有"挥空"感 |
| 处决/背刺 | 需要独立的镜头动画和特效组合 |
| 弹反（Parry） | 需要独特的音效和视觉标识 |
| 韧性系统 | 不同韧性下受击反馈不同 |

### 1.3 打击感数据流（v2 架构）

```
Q ── 代表 服务器端执行
R ── 代表 网络 RPC 传输
C ── 代表 所有客户端执行
L ── 代表 仅本机客户端执行
```

```
[Server] 武器碰撞命中
  │
  │  Q  ASL_WeaponBase::ApplyDamageToOverlappingActors()
  │     ├── 计算伤害 → GAS ApplyGameplayEffectSpecToSelf
  │     └── TriggerHitFeedback(Actor, HitLocation, Severity)
  │
  │  Q  TriggerHitFeedback()
  │     └── 填充 FHitFeedbackData { Severity, Instigator, Target, HitLocation }
  │
  │  R  Multicast_OnHitFeedback(Data)    -- NetMulticast, Reliable
  │
  ▼
[All Clients]  Multicast_OnHitFeedback_Implementation()
  │
  │  C  GlobalDelegatesManager::BroadcastHitFeedback(Data)
  │     └── OnHitFeedback 广播
  │
  │  C  HitFeedbackManagerComponent::OnHitFeedback(Data)  -- 订阅委托
  │     │
  │     ├── C  ApplyHitStop()
  │     │      ├── 攻击者.CustomTimeDilation = 0.001f
  │     │      ├── 受击者.CustomTimeDilation = 0.001f
  │     │      └── FTimerHandle → 恢复 1.0f
  │     │
  │     └── L  本机角色判定（是否是攻击者/受击者）
  │            ├── PlayHitCameraShake()    → PlayerCameraManager
  │            └── PlayHitScreenEffect()   → StartCameraFade
  │
  ▼
[HitStop 管理]  HitStopTimerHandles 位于 HitFeedbackManagerComponent
  │
  ├── 不随武器销毁丢失（组件生命周期 ≥ 武器生命周期）
  └── EndPlay 时自动恢复所有暂停的 Actor
```

**注意：**
- Hit Stop 通过 CustomTimeDilation 实现，只暂停攻击者和受击者两个 Actor，不影响摄像机和其他 AI
- Camera Shake 和屏幕特效只在本机客户端执行，不进行网络同步
- 所有打击感参数（HitStop 时长、Shake 缩放）集中在 HitFeedbackManagerComponent 的 UPROPERTY(EditDefaultsOnly) 中，可在蓝图编辑器中调整

## 2 命中停顿（Hit Stop / Freeze Frame）

### 2.1 原理

命中目标时，攻击者和目标同时暂停运动若干帧，模拟"砍进去卡住了"的物理感。

```
时间轴：
  帧 0：武器碰撞到目标
  帧 0~12：Hit Stop（攻击者 + 目标 动画暂停）
  帧 13：恢复播放
```

### 2.2 UE4 实现方案

方案A：全局 Time Dilation（不推荐） - 会影响所有 Actor 包括相机
方案B：按 Actor 暂停（推荐） - 通过 CustomTimeDilation 分别控制

```cpp
// 在 ApplyDamageToOverlappingActors 中命中后调用
// 暂停攻击者 + 目标，使用 CustomTimeDilation = 0.001f
// 定时恢复（通过 FTimerHandle）
```

### 2.3 参数参考

| 武器类型 | Hit Stop 时长 | 备注 |
|---------|--------------|------|
| 匕首/短刀 | 4~6 帧 (0.067~0.1s) | 轻快，停顿短 |
| 长剑 | 8~12 帧 (0.13~0.2s) | 适中 |
| 大剑/巨锤 | 12~18 帧 (0.2~0.3s) | 沉重，停顿长 |
| 处决/背刺 | 20~30 帧 (0.33~0.5s) | 特殊演出感 |
| 弹反成功 | 15~20 帧 (0.25~0.33s) | 突出"叮"的瞬间 |
| 命中墙壁/盾牌 | 4~8 帧 | 比命中肉体短 |
| 挥空（未命中） | 0 | 不暂停 |

### 2.4 进阶技巧

- 差异化 Hit Stop：命中头部 +3 帧，命中护甲 -2 帧
- 随距离衰减：武器尖端 vs 根部，停顿可以有差异
- 多人联机时：Hit Stop 只在攻击者和受击者的客户端生效，不暂停其他人

## 3 相机震动（Camera Shake）

### 3.1 UE4 实现

推荐使用 UE4.26 的 Camera Shake Base（新版 Perlin Noise 振荡器），可叠加多个震荡器。

```cpp
// 触发点：命中判定处
PC->ClientStartCameraShake(ShakeClass, Scale);
```

### 3.2 参数参考

| 事件 | 振幅 | 频率 | 持续时间 |
|------|------|------|---------|
| 轻击命中 | 0.3~0.5 | 8~10 Hz | 0.1s |
| 重击命中 | 0.8~1.2 | 6~8 Hz | 0.2s |
| 处决 | 1.5~2.0 | 4~6 Hz | 0.4s |
| 弹反成功 | 0.5~0.8 | 10~12 Hz | 0.15s |
| 被重击 | 1.0~1.5 | 6~8 Hz | 0.25s |
| Boss 攻击 | 2.0~3.0 | 3~5 Hz | 0.3s |

### 3.3 注意事项

- 只在受击者视角附近触发，不是全地图
- 多人联机时各客户端独立震动
- Hit Stop 结束时开始 Camera Shake，延迟 2~3 帧更自然

## 4 屏幕特效（Screen Effect）

### 4.1 受击闪白/闪红

命中瞬间在屏幕边缘叠加半透明图层的闪烁效果。通过 Client RPC 通知各客户端。

| 事件 | 闪屏 | FOV Punch | 持续时间 |
|------|------|-----------|---------|
| 轻击命中 | 不闪 | -2度 | 0.1s |
| 重击命中 | 白闪 0.2 | -5度 | 0.2s |
| 被轻击 | 红闪 0.3 | 无 | 0.15s |
| 被重击 | 红闪 0.6 | -3度 | 0.25s |
| 处决触发 | 白闪 1.0 | -8度 | 0.4s |
| 死亡 | 红闪 -> 灰度 | 无 | 1.0s+ |

### 4.2 FOV Punch

命中瞬间短暂推近 FOV，模拟冲击感。通过 CameraManager 的 FOV 插值实现。

## 5 音效（Audio）

### 5.1 音效分类

| 类别 | 触发时机 | 作用 |
|------|---------|------|
| 挥空音效（Whoosh） | 攻击动画执行中 | 传递武器速度和重量感 |
| 命中音效（Hit） | 碰撞判定瞬间 | 传递伤害质感 |
| 弹刀音效（Clang） | 命中盾牌/硬物 | 传递"没打穿"的挫败感 |
| 受击喊叫（Grunt） | 受击瞬间 | 传递伤害严重程度 |
| 处决音效（Execute） | 处决动画全程 | 强化演出感 |
| 环境音效（Environment） | 命中墙壁/地面 | 传递环境交互 |

### 5.2 参数参考

**挥空音效**：匕首 - 高频短促；长剑 - 中频中等；大剑 - 低频长

**命中音效**：
- 轻击肉体：短促"噗"声 + 骨骼脆响
- 重击肉体：沉闷"咚"声 + 骨头断裂声
- 命中铠甲：清脆"叮"声 + 金属震颤
- 命中盾牌：尖锐"铛"声 + 高频余音
- 命中墙壁：沉闷"砰"声

### 5.3 重要原则

- 命中音效应**比 Hit Stop 提前 1~2 帧播放**，否则 Hit Stop 期间音效被暂停
- 挥空音效 pitch 随攻速变化
- 多段连击每段音效应有细微差异

## 6 粒子与视觉特效（VFX）

### 6.1 命中特效

| 命中对象 | 粒子效果 | 贴花 |
|---------|---------|------|
| 肉体（轻击） | 少量红色粒子 | 血迹喷溅 |
| 肉体（重击） | 大量红色粒子 + 碎片 | 大片血迹 |
| 金属铠甲 | 橙色火花粒子 | 划痕 |
| 盾牌 | 大量火花 + 冲击波 | 无 |
| 墙壁/地面 | 碎石/灰尘粒子 | 划痕 |
| 处决 | 特写 + 慢动作 + 血雾 | 大范围血迹 |

### 6.2 武器轨迹特效

武器挥动时在模型后方拖出流光/残影，速度越快流光越长。不同武器类型使用不同颜色。

### 6.3 受击者外观反馈

- 受伤泛红：受击部位材质变红（通过 Material Instance Dynamic）
- 护甲碎裂：护甲破损视觉提示
- 流血：伤口持续飘出粒子（可选）

## 7 动画节奏（Animation Rhythm）

### 7.1 攻击动画关键帧

```
帧 0~5：    预备（Anticipation）-- 武器后拉，蓄势
帧 5~15：   攻击（Active）      -- 武器向前挥出
帧 15~17：  命中（Impact）      -- 碰撞判定 + Hit Stop
帧 17~25：  穿透（Follow-through）-- 武器继续运动
帧 25~40：  收力（Recovery）    -- 回到 Idle
```

类魂节奏特点：预备长、命中集中、收力长不能取消。

### 7.2 攻击类型节奏

**轻攻击**：预备 10 帧 -> 攻击 8 帧 -> 收力 15 帧，总 ~0.55s
**重攻击**：预备 20~40 帧（可蓄力）-> 攻击 12 帧 -> 收力 25 帧，总 ~0.95~1.28s
**处决**：预备 5 帧 -> 演出 40~60 帧 -> 收力 15 帧

## 8 受击反馈（Hit React）

### 8.1 受击动画层级

| 层级 | 触发条件 | 表现 | 硬直 |
|------|---------|------|------|
| Lv0 | 轻击命中 | 无受击（仅闪烁） | 0s |
| Lv1 | 轻击 + 低韧性 | 轻微后仰 | 0.3s |
| Lv2 | 重击 + 中韧性 | 大幅度后仰 | 0.6s |
| Lv3 | 重击 + 低韧性 | 击退（踉跄） | 0.8s |
| Lv4 | 特殊攻击 | 击飞（浮空） | 1.0s+ |
| Lv5 | 处决 | 特殊受击动画 | 处决动画控制 |

### 8.2 关键细节

- 受击动画不可被新连招覆盖（防止无限连）
- 受击结束后进入霸体帧（防止被压起身）
- 韧性条可视化：血条下方显示韧性恢复动画

## 9 伤害数字（Damage Number）

| 属性 | 建议值 |
|------|--------|
| 字体 | 粗体、淡黄色 |
| 大小 | 小 30px，大 60px |
| 颜色 | 普通-白/淡黄、暴击-金色、属性伤害-对应色 |
| 动画 | 向上飘出 + 淡出（0.8~1.2s） |
| 多段合并 | 同一次攻击的多段合为一个数字 |

暴击时数字加大 + 加粗 + 金色，伴随独立暴击音效和粒子。

## 10 调试与测量

### 10.1 打击感调试菜单

建议保留调试菜单：
- Hit Stop 时长 | Camera Shake 强度 | 闪屏强度 | 实时可调
- 每次命中输出日志：武器+目标+HitStop 帧数+震动幅值

### 10.2 参数配置化

所有打击感参数应该存在 DataTable 中（FImpactConfig），按武器类型 + 命中表面材质查询，可在编辑器热重载。

### 10.3 可测量指标

| 指标 | 目标值 |
|------|--------|
| 输入到命中的延迟 | < 8帧 (133ms) |
| 命中到反馈的总延迟 | < 3帧 (50ms) |
| 连招接续窗口长度 | 5~8帧 |
| 空挥时间比例 | <= 20% |
