> 设计目标：将现有客户端本地执行的操作迁移为服务器权威（Server-Authoritative）模式

> 关联系统：GAS、战斗系统、角色状态机、AI

| **轻击/重击输入** | 客户端本地执行？ | ❌ 待确认 | **高** |
| **闪避/翻滚** | 客户端本地执行？ | ❌ 待确认 | **高** |

| **姿态切换** | 客户端本地执行？ | ❌ 待确认 | **中** |
| **锁定目标** | 客户端本地执行？ | ❌ 待确认 | **中** |
| **装备切换** | 客户端本地执行？ | ❌ 待确认 | **中** |
| **移动输入** | CharacterMovement 内置权威 | ✅ UE4 原生 | 低 |

### 1.2 输入路径链（待审计）

以攻击输入为例，需要审计的完整调用链：

```
玩家按键
  → ASL_PlayerControllerBase::OnLightAttackPressed()
    → ProcessComboInput()
      → ComboManagerComponent::SomeMethod()
        → Character->Attack()
          → GAS::ActivateAbility()     ← GameplayEffect 是服务器应用的？
          → 伤害计算                    ← 在客户端还是服务器？
          → 动画通知回调                ← 谁触发？
```

其他操作（闪避、翻滚、换装备）同理，需要逐个跟踪。

## 2 总体架构

### 2.1 权威分层

```
                    ┌─────────────────────────────┐
                    │   服务器权威（Server Only）    │
                    │  · GameMode / GameState      │
                    │  · 伤害计算                  │
                    │  · GameplayEffect 应用        │
                    │  · AI 决策                    │
                    │  · 关卡进度/波次              │
                    │  · 物品消耗/装备变更           │
                    └─────────────────────────────┘
                               │
                    ┌──────────┴──────────┐
                    │  服务器→客户端复制    │
                    │  (Replicated)        │
                    └──────────┬──────────┘
                               │
                    ┌──────────┴──────────┐
                    │   客户端预测          │
                    │  · 移动预测           │
                    │  · 动画表现           │
                    │  · UI 响应            │
                    └─────────────────────┘
```

### 2.2 修改模式

对每个操作采用统一模式：

```
当前（客户端本地）:
  按键 → 直接执行逻辑

改造后（Server RPC + 客户端预测）:
  按键 → ServerRPC → 服务器执行权威逻辑 → 复制结果到客户端
       ↓ (可选)
       客户端预测（先播放表现，服务器结果覆盖）
```

## 3 改造步骤

### Step 1 — 审计全部输入路径（预计 1-2 天）

对以下文件进行逐函数审计，标记出所有客户端本地执行、但应该走服务器权威的逻辑点：

- `SL_PlayerControllerBase.cpp` — 所有 OnXxxPressed/Released 回调
- `SL_CharacterBase.cpp` — 攻击/闪避/状态切换方法
- `SL_ComboManagerComponent.*` — 连招状态机
- `SL_CombatantComponent.*` — 战斗相关
- `SL_MovementComponent.*` — 特殊移动（闪避/翻滚）
- `SL_EquipmentComponent.*` — 装备切换

**输出**：一份完整的函数调用链表格，标注每条链的权威状态。

**验收**：审计表格完成，团队评审通过。

---

### Step 2 — 连招系统服务器权威改造（预计 2-3 天）

**连招（Combo）是战斗系统的核心状态机，必须在服务器上保持权威。**

改动内容：
1. 攻击输入 → `Server_ComboInput` RPC
2. `ComboManagerComponent` 的状态只在服务器上变更
3. 客户端发送输入后通过 RepNotify 接收连招状态变化
4. 动画通知（蒙太奇回调）走服务器判定

**风险点**：
- 连招窗口判定时序（客户端延迟导致连招断开）
- 动画与服务器状态的同步

**验收**：
- 双实例测试：客户端A攻击，客户端B能看到A的连招动画
- 延迟模拟下连招仍然正确判定
- 客户端预测错误时服务器状态能修正

---

### Step 3 — 闪避/翻滚服务器权威改造（预计 1-2 天）

改动内容：
1. 闪避输入 → `Server_Dodge` RPC
2. 闪避的无敌帧在服务器判定
3. 特殊移动（翻滚距离、方向）服务器权威

**验收**：
- 灵体客户端闪避，房主能看到闪避动画和位移
- 闪避无敌帧判定以服务器为准

---

### Step 4 — 装备切换服务器权威改造（预计 1-2 天）

改动内容：
1. 装备切换 → `Server_SwitchEquipment` RPC
2. 武器 Mesh 切换由服务器触发
3. 装备属性变更走 GAS GameplayEffect 服务器应用

**验收**：
- 灵体切换武器，房主看到武器变化
- 武器属性（攻击力等）正确同步

---

### Step 5 — 状态同步完善（预计 2-3 天）

改动内容：
1. 移动模式（步行/跑步/冲刺）服务器权威
2. 姿态（站立/蹲下）服务器权威
3. 锁定目标同步
4. 角色属性（血量/体力/魔法）定期校验

**验收**：
- 房主看到灵体的移动模式正确
- 血量/体力值双方一致
- 锁定目标正确复制

---

### Step 6 — 召唤系统适配（预计 1 天）

改动内容：
1. 确认灵体的所有输入都已经过 Server RPC
2. 灵体造成的伤害走服务器计算
3. 灵体受到的伤害走服务器判定
4. AI 对灵体的感知正常

**验收**：
- 灵体攻击敌人造成伤害
- 敌人攻击灵体造成伤害
- 灵体死亡/遣返流程正常

---

### Step 7 — 压力测试与边界（预计 1-2 天）

测试内容：
1. 高延迟模拟（`-PktLag=` 命令行参数）
2. 断线重连
3. 两个灵体同时存在
4. 灵体在房主断线时的表现

**验收**：
- 延迟 100ms 下攻击仍然有正常的反馈
- 断线后灵体被遣返
- 无崩溃

## 5 风险与注意事项

### 5.1 ALS（Advanced Locomotion System）兼容性
项目使用 ALS 的移动/动画系统，ALS 的移动预测是客户端预测模式。改造时需要确保：
- 不破坏 ALS 的移动预测（CharacterMovement 原生支持）
- 只在 ALS 之上叠加的**操作层**（攻击、闪避、交互）做服务器权威

### 5.2 GAS 的天然权威性
GAS（GameplayAbilitySystem）本身设计就是服务器权威的：
- `ActivateAbility()` 只在服务器调用
- `GameplayEffect` 默认由服务器应用
- 客户端通过 `AbilityTask` 进行预测

现有的 `GrantAbilities` 已有 `HasAuthority()` 守卫 ✅

### 5.3 动画与状态不同步
最常见的 CS 问题：客户端播放了攻击动画，但服务器判定攻击未命中。
- 解决方案：服务器播放蒙太奇 → `Multicast` 到所有客户端
- 客户端预测攻击动画用于手感，服务器最终覆盖

### 5.4 调试工具
建议在后缀测试中使用命令行参数模拟网络条件：
```
-PktLag=100          模拟 100ms 延迟
-PktLoss=5           模拟 5% 丢包率
-PktOrder=1          模拟乱序到达
```
